│ Plan to implement                                                            │
│                                                                              │
│ Zorky: Interactive Fiction Engine with LLM Parser                            │
│                                                                              │
│ Context                                                                      │
│                                                                              │
│ Build a text adventure game engine where an LLM replaces the rigid parser    │
│ from classic games like Zork. The player types natural language ("grab the   │
│ lantern off the table") and the LLM maps it to a structured game action. The │
│  world model is the source of truth — the LLM interprets, never invents.     │
│                                                                              │
│ Architecture                                                                 │
│                                                                              │
│ Player Input → LLM Parser → ParsedAction → Game Engine → ActionResult →      │
│ Narrator → Display                                                           │
│                                                 ↑                            │
│                                           GameState (source of truth)        │
│                                                                              │
│ Key design rule: The LLM receives current game context (room, items, exits,  │
│ inventory) and returns a structured ParsedAction. The engine validates and   │
│ executes it. They never call each other — only share the ParsedAction type.  │
│                                                                              │
│ File Structure                                                               │
│                                                                              │
│ Zorky/                                                                       │
│ ├── package.json / tsconfig.json                                             │
│ ├── src/                                                                     │
│ │   ├── index.ts                  # Entry point + game loop                  │
│ │   ├── types.ts                  # All shared type definitions              │
│ │   ├── engine/                                                              │
│ │   │   ├── GameEngine.ts         # State management, entity resolution,     │
│ action dispatch                                                              │
│ │   │   ├── ActionRegistry.ts     # Action handlers (move, take, use,        │
│ examine, etc.)                                                               │
│ │   │   └── ActionValidator.ts    # Helper utilities for precondition checks │
│ │   ├── parser/                                                              │
│ │   │   ├── LLMProvider.ts        # Interface + factory function             │
│ │   │   ├── AnthropicProvider.ts  # Claude implementation using structured   │
│ outputs + Zod                                                                │
│ │   │   └── RuleBasedParser.ts    # Regex/keyword fallback (no API key       │
│ needed)                                                                      │
│ │   ├── world/                                                               │
│ │   │   ├── WorldLoader.ts        # Converts WorldDefinition → initial       │
│ GameState                                                                    │
│ │   │   └── starterWorld.ts       # The 5-room starter world data            │
│ │   └── ui/                                                                  │
│ │       ├── Terminal.ts           # Node readline wrapper                    │
│ │       └── Narrator.ts           # Formats ActionResults into styled text   │
│                                                                              │
│ Starter World                                                                │
│                                                                              │
│                 [Tower Room]                                                 │
│                      |                                                       │
│                     (up)                                                     │
│                      |                                                       │
│   [Garden] --east-- [Great Hall] --north-- [Library]                         │
│                      |                                                       │
│                    (down, locked)                                            │
│                      |                                                       │
│                   [Cellar]                                                   │
│                                                                              │
│ Puzzle flow:                                                                 │
│ 1. Start in Great Hall. Door down is locked.                                 │
│ 2. Gardener in Garden hints about the library.                               │
│ 3. Examine the alcove in Library → reveals rusty key.                        │
│ 4. Use key → unlocks cellar door.                                            │
│ 5. Open chest in Tower Room → get gold amulet.                               │
│ 6. Use amulet on pedestal in Cellar → win.                                   │
│                                                                              │
│ Action System                                                                │
│                                                                              │
│ Actions: move, take, drop, use, examine, look, inventory, talk, open, help,  │
│ quit                                                                         │
│                                                                              │
│ Each has a validate(action, state) → ValidationResult and execute(action,    │
│ state) → ActionResult. Puzzle-specific logic (use key on door, use amulet on │
│  pedestal) lives in a small lookup table within the use handler.             │
│                                                                              │
│ LLM Integration                                                              │
│                                                                              │
│ - Interface: LLMProvider.parseInput(playerInput, context) → ParsedAction     │
│ - Anthropic implementation: Uses @anthropic-ai/sdk with Zod structured       │
│ outputs to guarantee the response schema. Sends current room context +       │
│ player input, gets back { actionType, target, secondaryTarget, direction,    │
│ confidence }.                                                                │
│ - Rule-based fallback: Verb-noun regex parser handles go north, take key,    │
│ use X on Y, single-letter shortcuts (n, s, i, l, x). Used automatically when │
│  no ANTHROPIC_API_KEY is set.                                                │
│ - Entity resolution: The engine fuzzy-matches free-text target names from    │
│ the parser against visible entity names/aliases to resolve to IDs.           │
│                                                                              │
│ Implementation Order                                                         │
│                                                                              │
│ 1. package.json, tsconfig.json — project setup, npm install                  │
│ 2. types.ts — all type definitions (the contract)                            │
│ 3. world/starterWorld.ts + world/WorldLoader.ts — world data + state init    │
│ 4. engine/ActionValidator.ts — utility helpers                               │
│ 5. engine/ActionRegistry.ts — all action handlers                            │
│ 6. engine/GameEngine.ts — orchestrator                                       │
│ 7. parser/RuleBasedParser.ts — enables end-to-end play without API key       │
│ 8. parser/LLMProvider.ts — factory                                           │
│ 9. ui/Terminal.ts + ui/Narrator.ts — I/O                                     │
│ 10. index.ts — wire everything, playable with rule-based parser              │
│ 11. parser/AnthropicProvider.ts — LLM integration (add last)                 │
│                                                                              │
│ Tech Stack                                                                   │
│                                                                              │
│ - TypeScript (strict), Node.js >=20, ES modules                              │
│ - @anthropic-ai/sdk + zod for structured LLM output                          │
│ - tsx for dev mode (npm run dev)                                             │
│ - Node readline for terminal I/O                                             │
│                                                                              │
│ Verification                                                                 │
│                                                                              │
│ 1. npm run dev — game starts, shows welcome + Great Hall description         │
│ 2. Play through with rule-based parser: north, examine alcove, take key,     │
│ south, use key on door, down, etc.                                           │
│ 3. Complete the full puzzle flow to victory                                  │
│ 4. Set ANTHROPIC_API_KEY and replay with natural language: "I want to go     │
│ check out the library", "what's in that alcove?", "grab the key"             │
│ 5. npm run build — clean TypeScript compilation                              │
