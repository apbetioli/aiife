# State persistence (save and restore)

State persistence enables players to serialize their current game state (player location, room visited flags, carried inventory, object positions) to disk in a named save slot, and restore that exact state in a subsequent turn or session.

## Sub-features

- `save-default`: saves game state to `.save-<world_id>-default.json`.
- `save-named-slot`: saves game state to a sanitized custom slot `.save-<world_id>-<slot>.json`.
- `restore-slot`: reads a save file from disk, restores Immer state, and re-triggers `look` to reorient the player.
- `restore-missing`: cleanly reports when an requested slot file does not exist.

## How to get to it (user POV)

- Type `save` to save to the default slot.
- Type `save <slot-name>` (e.g. `save slot1`, `save verify-test`).
- Type `restore` or `load` to restore the default slot.
- Type `restore <slot-name>` or `load <slot-name>`.

## Driving it with control-aiife

Preconditions:

- `control-aiife doctor` returns code 0.
- Starting game is `the-great-hall`.
- No conflicting save file named `.save-the_great_hall-verify-save.json`.

- **Save state after mutation.** Move north to Library and save to slot `verify-save`. Run:
  `control-aiife drive --game the-great-hall --commands "north;save verify-save;quit" --save-slot verify-save --output-dir artifacts/verify-aiife/save-named`
  Observable result: Terminal outputs `Game saved to slot "verify-save".` Proof file `artifacts/verify-aiife/save-named/save-state.json` is created with `"current_room": "library"`.
- **Restore saved state.** In a new session starting from Great Hall, restore `verify-save`. Run:
  `control-aiife drive --game the-great-hall --commands "restore verify-save;look" --output-dir artifacts/verify-aiife/restore-named`
  Observable result: Terminal displays `The Library` immediately upon restore without typing `north`, reorienting the player in the restored room.
- **Restore non-existent slot.** Request an unknown slot. Run:
  `control-aiife drive --game the-great-hall --commands "restore nonexistent_slot_123" --output-dir artifacts/verify-aiife/restore-missing`
  Observable result: Terminal responds `No save file found for slot "nonexistent_slot_123".` without crashing or changing state.

## Gotchas

- Slot names are sanitized with `replace(/[^a-zA-Z0-9_-]/g, "")`. Punctuation and spaces are stripped.
- Attempting to restore a save file generated by a different game world (e.g. restoring a Zork save into The Great Hall) is rejected by `world_id` validation.
- Always use distinct slot names (e.g. prefix with `verify-`) during automated runs to prevent clobbering manual player saves.
- Run `control-aiife cleanup` after tests to prune temporary test save files.
